# 0.5 Part D: E-mails Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Zenc-branded Portuguese account e-mails (confirmation, recovery, e-mail change, invite that names the business) and a 24-hour reminder e-mail for customers with an account, sent through Resend next to the existing push, with an on/off setting on the Zenc account.

**Architecture:** Account e-mails are Supabase auth templates under `supabase/templates/`, wired in `config.toml`. The reminder e-mail is its own outbox row (event type `appointment.reminder_email`) created by the existing 24 h enqueue, so retries never touch push. `dispatch-notifications` gets an e-mail branch: a pure builder makes the message, a small Resend client sends it (Idempotency-Key = outbox id) or logs and skips without an API key.

**Tech Stack:** Supabase auth templates (Go templates), plpgsql + pgTAP, Deno Edge Function (tested from Jest like the existing dispatcher), Resend HTTP API, Expo/React Native screens, Jest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-25-v05-readiness-design.md` (section D, decision 9).

## Global Constraints

- Portuguese only. Say **estabelecimento / negócio**, never "barbearia" / "barbershop". Account e-mails (confirmation, recovery, e-mail change) are ZENC-branded and name NO business; only the invite names it: "Você foi convidado para <negócio> na Zenc".
- Email-safe HTML: tables and inline styles, wordmark "ZENC." as text, one main button plus a fallback link. No `<style>` block, no images, no web fonts.
- Reminder: customers with an account only, 24 h before, ALWAYS in addition to push, same 23-25 h window as 0022. Text: "Lembrete: amanhã às HH:MM, <serviço> com <profissional> em <estabelecimento>", the address, button "Ver meus agendamentos" to the business link, footer "Para não receber, desative em Configurações > Notificações".
- Setting "Lembretes por e-mail": a `profiles` column, default true, applies to every business (the account is a Zenc account), in the customer notification settings.
- Each e-mail is its own outbox row: a retry never resends push and vice versa. Sending: Resend HTTP API, `RESEND_API_KEY` and `EMAIL_FROM` env; without a key it logs and skips.
- Out of scope: customers without an account, a booking-confirmation e-mail, a 2 h reminder.
- Migration `0082`, pgTAP `063` (re-check the numbers on `main`: A took `0080`/`061`/`P0046`, C took `0081`/`062`/`P0044`/`P0045`). No new error code.
- Strict TDD, one commit per task, trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Read-only shell commands through `rtk`. Never `supabase db reset`.
- Gates before the PR: `npm run typecheck`, root `npm run lint`, full `npx jest` (no "did not exit"), `supabase test db`, Playwright chromium + firefox + webkit whole suite per `docs/testing.md` (`.env.local` aside and restored, default base URL), static export.

-- supabase/migrations/0082_email_reminders.sql
-- 1. The account setting. A Zenc account has one setting for every business (the account is not tied to one).
alter table public.profiles add column email_reminders boolean not null default true;

create function public.set_email_reminders(p_enabled boolean)
returns void
language plpgsql
security definer
set search_path = pg_catalog, public, pg_temp
as $$
begin
  if auth.uid() is null then
    raise exception using errcode = '42501', message = 'FORBIDDEN';
  end if;

  update public.profiles set email_reminders = coalesce(p_enabled, true), updated_at = now() where user_id = auth.uid();
end;
$$;

revoke all on function public.set_email_reminders(boolean) from public, anon;
grant execute on function public.set_email_reminders(boolean) to authenticated;

-- 2. The outbox accepts the e-mail event (list copied from 0062 plus the new type).
alter table public.notification_outbox drop constraint notification_outbox_event_type_check;
alter table public.notification_outbox add constraint notification_outbox_event_type_check check (event_type in (
  'appointment.booked', 'appointment.cancelled', 'appointment.rescheduled', 'appointment.reminder', 'recurrence.conflict',
  'appointment.confirmed', 'staff.awaiting_confirmation', 'staff.booked', 'staff.cancelled', 'staff.rescheduled',
  'recurrence.requested', 'recurrence.accepted', 'recurrence.rejected',
  'recurrence.cancel_requested', 'recurrence.cancel_accepted', 'recurrence.cancel_declined',
  'payout.due', 'payout.paid',
  'appointment.reminder_email'));

-- 3. Reminders: the push insert of 0022 unchanged, plus one e-mail row per eligible appointment (its own event key, so push and
-- e-mail are retried independently). The return value stays the number of push rows.
create or replace function public.enqueue_notification_reminders()
returns integer
language plpgsql
security definer
set search_path = pg_catalog, public, pg_temp
as $$
declare
  inserted_count integer;
begin
  insert into public.notification_outbox (
    event_key, event_type, recipient_user_id, appointment_id, payload
  )
  select
    format('appointment:%s:reminder:24h', appointments.id),
    'appointment.reminder',
    customers.user_id,
    appointments.id,
    jsonb_build_object(
      'appointment_id', appointments.id,
      'shop_id', appointments.shop_id,
      'starts_at', appointments.starts_at,
      'ends_at', appointments.ends_at,
      'service_name', appointments.service_name_snapshot,
      'status', appointments.status
    )
  from public.appointments
  join public.customers
    on customers.id = appointments.customer_id
   and customers.shop_id = appointments.shop_id
  where appointments.status in ('scheduled', 'confirmed')
    and customers.user_id is not null
    and appointments.starts_at > clock_timestamp() + interval '23 hours'
    and appointments.starts_at <= clock_timestamp() + interval '25 hours'
  on conflict (event_key) do nothing;

  get diagnostics inserted_count = row_count;

  insert into public.notification_outbox (
    event_key, event_type, recipient_user_id, appointment_id, payload
  )
  select
    format('appointment:%s:reminder:24h:email', appointments.id),
    'appointment.reminder_email',
    customers.user_id,
    appointments.id,
    jsonb_build_object(
      'appointment_id', appointments.id,
      'shop_id', appointments.shop_id,
      'starts_at', appointments.starts_at,
      'service_name', appointments.service_name_snapshot,
      'professional_name', professionals.name,
      'shop_name', shops.name,
      'shop_slug', shops.slug,
      'shop_timezone', shops.timezone,
      'shop_address', concat_ws(', ',

        nullif(btrim(shops.address_district), ''),

// supabase/functions/dispatch-notifications/resend.ts
import type { Email } from "./email.ts";

export type OutgoingEmail = Email & { to: string };
export type EmailSendResult = { error?: string; ok: boolean; skipped?: boolean };

type Options = { apiKey?: string; fetch?: typeof fetch; from?: string; log?: (message: string) => void };

// Resend HTTP API. The Idempotency-Key (the outbox id) makes a retry after a crash between "sent" and "marked sent" harmless.
export function createResendSender({ apiKey, fetch: send = fetch, from, log = console.warn }: Options) {
  return async (email: OutgoingEmail, idempotencyKey: string): Promise<EmailSendResult> => {
    if (!apiKey || !from) {
      log("RESEND_API_KEY or EMAIL_FROM is not set; skipping e-mail");
      return { ok: true, skipped: true };
    }

    try {
      const response = await send("https://api.resend.com/emails", {
        body: JSON.stringify({ from, html: email.html, subject: email.subject, text: email.text, to: [email.to] }),
        headers: { Authorization: `Bearer ${apiKey}`, "Content-Type": "application/json", "Idempotency-Key": idempotencyKey },
        method: "POST",
      });

      return response.ok ? { ok: true } : { error: `Resend HTTP ${response.status}`, ok: false };
    } catch (error) {
      return { error: error instanceof Error ? error.message : "Resend request failed", ok: false };
    }
  };
}
